# Сводка по базовым файлам проекта SCADA

Краткое описание каждого базового файла проекта и сценарии, когда его нужно править.

---

## `SCADA.sln`

**Назначение:** файл решения. Объединяет проекты в одну группу и описывает конфигурации сборки (`Debug`/`Release`).

**Когда править:** почти никогда. Редактируется автоматически через команды `dotnet`.

| Use case | Команда |
|---|---|
| Добавить проект в solution | `dotnet sln add Project/Project.csproj` |
| Удалить проект из solution | `dotnet sln remove Project/Project.csproj` |
| Создать solution заново | `dotnet new sln` |

**Не трогать руками:** список проектов, GUID и секции конфигураций.

---

## `SCADA/SCADA.csproj`

**Назначение:** файл проекта. Описывает SDK, целевую версию .NET, NuGet-пакеты, ресурсы и ресурсы.

**Когда править:**

| Use case | Как править |
|---|---|
| Добавить NuGet-пакет | `dotnet add package PackageName` или вручную `<PackageReference>` |
| Добавить ссылку на другой проект | `dotnet add reference Project/Project.csproj` или `<ProjectReference>` |
| Изменить версию .NET | Поменять `<TargetFramework>` |
| Включить дополнительные файлы как ресурсы | Добавить `<AvaloniaResource>`, `<Content>` или `<EmbeddedResource>` |
| Настроить публикацию | Добавить `<PublishSingleFile>`, `<SelfContained>`, `<RuntimeIdentifier>` |
| Изменить строгость компиляции | `<TreatWarningsAsErrors>`, `<Nullable>`, `<LangVersion>` |
| Добавить пустую папку в проект | `<Folder Include="Models\"/>` |

**Что делать не нужно:** вручную перечислять `.cs` файлы — SDK-style проект включает их автоматически.

---

## `SCADA/app.manifest`

**Назначение:** манифест Windows. Управляет правами, совместимостью ОС, DPI и другими Windows-специфичными настройками.

**Когда править:**

| Use case | Что добавить |
|---|---|
| Требовать права администратора | `<requestedExecutionLevel level="requireAdministrator"/>` |
| Настроить масштабирование на HiDPI-экранах | `<dpiAwareness>PerMonitorV2</dpiAwareness>` |
| Указать поддержку Windows 11 | Уже покрыто GUID Windows 10 |
| Изменить версию/имя в манифесте | `<assemblyIdentity version="1.2.3.0" name="SCADA.Desktop"/>` |

**Не трогать без нужды:** базовый манифест Avalonia нужен для корректной работы прозрачности окон и встроенных контролов.

---

## `SCADA/Program.cs`

**Назначение:** точка входа в приложение. Конфигурирует и запускает Avalonia.

**Когда править:**

| Use case | Что менять |
|---|---|
| Настроить Dependency Injection | Добавить инициализацию контейнера перед `StartWithClassicDesktopLifetime` |
| Настроить глобальное логирование | Заменить/расширить `.LogToTrace()` |
| Обработать аргументы командной строки | Добавить логику в `Main(string[] args)` |
| Обработать необработанные исключения | Подписаться на `AppDomain.CurrentDomain.UnhandledException` |
| Изменить способ запуска | Использовать другой lifetime вместо `StartWithClassicDesktopLifetime` |

**Не трогать без нужды:** базовый `BuildAvaloniaApp()` нужен и приложению, и визуальному дизайнеру.

---

## `SCADA/ViewLocator.cs`

**Назначение:** связывает ViewModel с соответствующей View по соглашению об именовании.

**Когда править:**

| Use case | Что делать |
|---|---|
| Имена View и ViewModel перестали совпадать | Добавить обработку особых случаев или переехать на словарь |
| Планируется trimming/AOT | Заменить рефлексию на явный словарь `ViewModel → View` |
| Нужно передавать зависимости в View | Перейти на DI-контейнер |
| Нужно кэшировать созданные View | Добавить кэш внутри `Build` |

**Типичная замена в серьёзных проектах:** явный словарь или DI-контейнер вместо рефлексии.

---

## `SCADA/App.axaml`

**Назначение:** ресурсы и глобальные настройки приложения: темы, стили, DataTemplates, кисти, конвертеры.

**Когда править:**

| Use case | Что добавить |
|---|---|
| Поменять тему | `RequestedThemeVariant="Dark"` / `"Light"` / `"Default"` |
| Добавить глобальные цвета/кисти | `<Application.Resources>` |
| Добавить глобальные стили | `<Application.Styles>` |
| Добавить конвертеры | `<Application.Resources>` |
| Подключить дополнительные темы или шрифты | `<Application.Styles>` |
| Регистрация альтернативных DataTemplates | `<Application.DataTemplates>` |

**Хорошая практика:** в больших проектах стили и ресурсы выносят в отдельные `.axaml` файлы и подключают через `<StyleInclude Source="..."/>`.

---

## `SCADA/App.axaml.cs`

**Назначение:** код приложения. Загружает `App.axaml` и создаёт главное окно при старте.

**Когда править:**

| Use case | Что менять |
|---|---|
| Создать главное окно через DI | `serviceProvider.GetRequiredService<MainWindow>()` |
| Передать зависимости в `MainViewModel` | Создавать ViewModel через DI |
| Обработать старт/закрытие приложения | Переопределить `OnFrameworkInitializationCompleted` или подписаться на события lifetime |
| Добавить глобальную обработку ошибок | Подписаться на `Application.Exit`, `Desktop.ShutdownRequested` и т.д. |
| Настроить навигацию между экранами | Инициализировать сервис навигации |

**Не забывать:** вызывать `base.OnFrameworkInitializationCompleted()` в конце метода.

---

## `SCADA/Views/*.axaml` и `*.axaml.cs`

**Назначение:** визуальное представление экрана или окна.

**Когда править `.axaml`:**

| Use case | Что делать |
|---|---|
| Изменить интерфейс | Добавлять/удалять/изменять контролы |
| Привязать данные к ViewModel | `{Binding PropertyName}` |
| Указать тип ViewModel | `x:DataType="vm:MainViewModel"` |
| Задать DataContext для дизайнера | `<Design.DataContext>` |
| Изменить иконку/заголовок окна | `Icon="..."`, `Title="..."` |

**Когда править `.axaml.cs` (code-behind):**

| Use case | Что делать |
|---|---|
| Обработать события окна | `Loaded`, `Closing`, `Closed` |
| Работать с элементами, требующими прямого доступа | Canvas, графики, WebView |
| Запускать сложные анимации | Код в обработчиках событий |
| Добавить attached properties или behaviors | Расширение функциональности XAML |

**Правило:** code-behind должен содержать только UI-специфичный код. Бизнес-логика — в ViewModel.

---

## `SCADA/ViewModels/*.cs`

**Назначение:** данные, состояние и логика экрана.

**Когда править:**

| Use case | Что делать |
|---|---|
| Добавить свойство для привязки | `[ObservableProperty] public partial string Name { get; set; }` |
| Добавить команду для кнопки | `[RelayCommand] private void Save() { ... }` |
| Добавить валидацию | Реализовать `IDataErrorInfo` или `INotifyDataErrorInfo` |
| Добавить асинхронную операцию | `async Task LoadDataAsync()` с командами |
| Получать данные из сервисов | Внедрить сервис через конструктор (DI) |

**Правило:** ViewModel не должна знать о конкретных контролах. Она работает со свойствами и командами.

## Общие принципы

1. **Руками правят:** View, ViewModel, `.csproj` (пакеты, настройки), `App.axaml` (ресурсы/стили), `App.axaml.cs` (DI, старт приложения).
2. **Через CLI правят:** `SCADA.sln` (добавление проектов), NuGet-пакеты.
3. **Редко трогают:** `Program.cs`, `app.manifest`, `ViewLocator.cs` (если нет особых требований).
4. **Не правят:** не перечисляют `.cs` файлы в `.csproj` — SDK делает это автоматически.
