## 2. Рабочие договорённости с пользователем

- **Обсуждаем до реализации.** Новая функция или изменение контракта —
  сначала изложить замысел и границы, потом ждать «да».
- **Коммит и push — только по явной просьбе.** Работа доводится до конца
  и остаётся в рабочем дереве; момент коммита решает пользователь.
- **Версия секции пакета до релиза = 1.** Совместимость не поддерживается:
  поменял раскладку — пересобери пакет. Версии не бампим.
- **Терминология:** сессионные теги (не «теги рабочего места»); инженерная
  и исполнительная поставка; редактор и рантайм.
- Обычные инструменты правки файлов, без скриптов-heredoc.

### Ключевые решения, которые легко забыть

- **Текста выражений в пакете нет нигде** — только байткод в `code.bin`
  и индексы. Правило сквозное: строковые шаблоны параметров навигации
  сборка разбирает и кладёт разобранными (литералы + индексы). Следствие:
  исходный словарь `Parameters` из пакета не восстанавливается, и **парсер
  скобок существует только в сборке**.
- **Адресация действий не выходит за границу своей схемы** (внутри тела
  шаблона — за границы экземпляра). Межсхемное состояние — сессионный тег:
  у него есть память и он не зависит от того, что сейчас на экране.
- **Область видимости имени элемента** — тело схемы или тело шаблона,
  считается до раскрытия экземпляров. Контейнер областью не делается:
  область появляется там, где появляется копирование.
- **Свойство под привязкой не задаётся действием** и не порождает событие
  изменения: пересчёт привязки затрёт заданное.
- **Цвет из выражения не делаем.** Формально ВМ его даёт (при `Direct`
  результат кастуется в ARGB), но ключ темы из числа не получится никогда —
  такой элемент молча выпал бы из перекраски проекта. Вычисляемый цвет —
  привязка со стопами.

## 4. Что дальше: C4, событие изменения свойства

Механизм универсальный (любой элемент, валидация по `ElementSchemas`),
а не «про контролы». Модель, формат и валидация — наши; гашение по
равенству и предел глубины каскада — Dev B.

Замысел: новый вид события `PropertyChanged` с полем «какое свойство»,
дальше обычная цепочка действий. Менять свойство в рантайме могут
`SetProperty` (C5) и сам контрол (C3), отсюда каскад и предел глубины.

### Мост «свойство → тег» (вариант A) — проверено, готово к реализации

Событие само по себе не доносит новое значение: действия читают теги,
а не свойства элементов. Выражения ходят в `TagTable` и пересчитываются
по эпохам — свойств там нет и не будет (ровно та причина, по которой
аварии сделаны тегами, а не функцией ВМ). Значит нужен мост: действие
«записать свойство элемента в тег», зеркальное C5.

Что выяснила проверка кода:

- строковые теги полноценны: `ITagTable.WriteString`/`ReadString`, общая
  эпоха, грязный пересчёт их покрывает;
- сессионные теги умеют строки (`SessionTagRouter.WriteString`) и пишутся
  локально — без сети, права `Operate` и аудита (`LocalRuntimeClient`,
  `WriteMixedAsync`);
- **операторской записи строк нет**: `TagWriteItem` — это `(TagId, double)`;
  в `IRuntimeClient` прямо записано, что строковый вариант — отдельная
  задача. Есть только системная `WriteLocalString`.

Отсюда граница моста:

| Свойство | Куда | Как |
|---|---|---|
| Number / Boolean / Choice | любой числовой тег | существующий путь, изменений ноль |
| String | только **сессионный** строковый тег | новый метод контракта, локальная запись |
| String | объектный строковый тег | ошибка сборки: операторская запись строк — M7 |
| Color | никуда | ARGB числом бессмысленно, запрет |

Добавка к контракту — одна:

```csharp
ValueTask<TagWriteResult> WriteStringAsync(TagId tag, string text,
    string requestedBy, CancellationToken ct = default);
```

Локально: сессионный тег → локальная запись; объектный → `Failed`
с пояснением. Та же проверка при сборке, чтобы инженер узнал не на объекте.

### Открытые вопросы (ждут ответа пользователя)

1. **Делаем C4 вместе с мостом сейчас** или C4 голым, а мост — вместе с C3?
   Мой довод за «сейчас»: мост от C3 не зависит, а без него C4 умеет только
   «что-то поменялось». При этом честно: **исходный сценарий журнала
   («выбрали строку → кнопка квитирует выбранную») до C3 не заработает** —
   свойства «выбранная строка» у журнала ещё не существует, свойства
   контролов появятся в C3.
2. **Префикс длины у записи события в секции.** Сейчас это единственная
   запись без него, а C4 добавляет ей поле (id свойства). Дать префикс
   заодно? Всё равно понадобится в C3, стоит десяток строк, версия
   секции остаётся 1.
