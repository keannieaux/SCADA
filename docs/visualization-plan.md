## 1. Принцип параллельной работы

**Механика исполнения не зависит от источника модели.** Схема сегодня
строится руками в коде — и вся работа Dev B над движком (привязки, стопы,
hit-test, кэши, события) ведётся против руками собранной схемы и
`SyntheticSchemeGenerator`. Упаковка и Core-модель подменяют только *источник*
данных, не механику. Поэтому Dev B не блокируется: сначала механика против
прототипа, потом замена источника.

Порядок для Dev B: **сначала механика (B0/B1), потом источник (B2)** — когда
пакетный формат появится, рискованная пересадка canvas уже позади.

### A5.9. Единый путь загрузки (перед A6)

Рантайм работает только с `.scadapkg`: dev-ветка `Directory.Exists`/`ProjectLoader`
в `RuntimeHost` — наследие M1–M2 (пакета не было, JSON был единственным входом).
Два пути обязаны давать идентичную конфигурацию — налог на каждую подсистему
(диагностика, аварии), и пути уже разошлись функционально (в dev схемы без
скомпилированных привязок, правила аварий требуют `ExpressionFactory` от
вызывающего). JSON — язык инженерной части (редактор, сборка), пакет — язык
исполнительной; единственный мост — `ProjectBuildService`.

Удаляется: dev-ветка в `RuntimeHost.BuildHost`, `RuntimeHostOptions.ExpressionFactory`,
dev-каталог в `SCADA.Server` (демо собирается в пакет, appsettings → .scadapkg),
тесты хоста переключаются на «собрать пакет во временную папку».

Остаётся: `ProjectLoader`/`ProjectWriter` — вход редактора и сборщика пакета
(позже перенести из `SCADA.Runtime` в инженерную сборку — косметика, при редакторе).

### Бэклог (зафиксировано, не в объёме A6)

- **Симуляция экранов:** `RuntimeHostOptions.Simulation` + подмена драйверов на
  `SimulatorDriver` в composition root + авто-сигналы по `DataType` для не-sim
  адресов (аналог → синус, дискрет → меандр). Кнопка «Запуск симуляции» в
  редакторе собирает тот же пакет и стартует хост с флагом — проверяется тот
  артефакт, который поедет на объект. К пути загрузки отношения не имеет.
- **Инкрементальная сборка (после замеров на большом проекте):** кэш секций по
  хэшам входов (`output/.buildcache/`), пересборка только изменённого; профиль
  быстрой сборки для редактора — zip в режиме store (без DEFLATE), параллельная
  компиляция схем. Ключевой задел, который дёшев сейчас и дорог потом:
  content-addressed пул code.bin (ссылка на выражение по хэшу текста, а не по
  позиции) — иначе пересборка одной схемы сдвигает индексы пула во всех секциях.
- **Hot reload схем (схемы — иммутабельные снимки, это дёшево):** атомарная
  подмена `SchemeCatalog` в рантайме по версии пакета + «эпоха схем», UI
  перезапрашивает открытый экран; опрос/аварии/архив не трогаются. Hot reload
  тегов/каналов/аварий — НЕ делаем (diff конфигураций с сохранением состояния —
  дорого и опасно); рестарт и так бесшовный (аварии из events.db, персистентные
  теги из файла, загрузка пакета — сотни мс).

## 3. Dev B — графика и UI (подробно)

### B0. Механика рантайма против прототипа — начинается немедленно

Работа в `SCADA.Graphics`, схема по-прежнему строится руками в коде.
Модель-прототип (классы привязок/стопов/свойств) создаётся локально в Graphics
**один-в-один по §3–4 концепта** — после A1 она заменяется using'ом на
Core-модель без переписи механики.

Порядок подзадач (каждая — отдельный коммит, экран работает на каждом шаге):

**B0.1 Реестр свойств и runtime-массив.**
Файлы: `SchemeElementRuntime.cs` (переписать), новый `PropertySchema.cs`.
- Прототип дескриптора свойства: id (int), тип, умолчание, флаг animatable.
- `SchemeElementRuntime`: вместо полей `Fill/Visible/RotationDegrees/...` —
  плоский массив значений, индексируемый id свойства + флаги QualityBad,
  BlinkActive. Текущие 8 каналов представить как свойства прототипа.
- Приёмка: руками собранная схема выглядит и ведёт себя как раньше.

**B0.2 Привязки и таблицы стопов.**
Файлы: `SchemeCanvas.cs` (`IsDirty`, `Recompute` — переписать цепочки if'ов),
новые `Binding.cs`, `StopTable.cs`.
- Привязка: скомпилированное выражение + id свойства + таблица стопов.
- Режимы: прямой (значение → свойство), дискретный (пороги),
  интерполированный (`SKColor.Lerp` для цвета, lerp для чисел).
- `IsDirty`: цикл по TagIndices привязок + volatile (B0.4) вместо 8 ручных
  проверок. `Recompute`: вычислить выражение → применить стопы → записать в
  ячейку свойства.
- Приёмка: существующие динамики (цвет по порогам, видимость, мигание,
  поворот, уровень, текст, позиция) работают через новую механику; демо
  «труба синий→красный по температуре» на интерполяции.

**B0.3 Автоматическое качество.**
- Если хоть один входной тег привязки `Quality != Good` — элемент получает
  флаг качества автоматически (без ручного QualityTagName; поле остаётся для
  особых случаев). Отображение через тему.
- Приёмка: обрыв связи в симуляторе серит все связанные элементы без
  настройки.

**B0.4 Volatile-привязки и время.**
- Флаг `volatile` у привязки: элемент пересчитывается каждый тик независимо
  от эпох. Текущее время передаётся в `EvaluationContext` (новое поле —
  согласовать с Dev A, это SCADA.Expressions).
- Приёмка: демо непрерывного вращения/бегущей строки; элемент без volatile не
  пересчитывается лишний раз (замер Tick в Debug).

**B0.5 Hit-test по реальной геометрии.**
Файл: `SchemeCanvas.cs` (`HandleClick`).
- `SKPath.Contains` (с учётом поворота и Kind) вместо прямоугольника.
- Приёмка: повёрнутый эллипс кликается по видимой фигуре, не по bbox.

**B0.6 Производительность рендера.**
Файлы: `SchemeDrawOperation.cs`, `SymbolCache.cs`, новый кэш шрифтов/картинок.
- Убрать per-frame создание `SKTypeface` (кэш по (семейство, размер));
  переиспользуемый буфер визуалов вместо нового List на кадр; куллинг по
  видимому viewport (элементы вне экрана не рисуются).
- Приёмка: `SyntheticSchemeGenerator` на 500+ элементов, Tick и Render не
  медленнее текущих замеров (Debug.WriteLine уже на месте); нагрузочный прогон
  с текстом на большинстве элементов.

**B0.7 События и действия.**
Файлы: `SchemeAction.cs`, `CompiledSchemeAction.cs`, `SchemeCanvas.cs`
(`ExecuteActions`).
- Модель: словарь событий (реализовать только Click, остальные — в формате
  прототипа); у действия — опциональное условие-выражение и Confirm как
  модификатор (`ConfirmAction` как отдельный шаг убрать).
- Запись — только через `WriteTagAsync` (уже так); ошибки записи показывать
  пользователю (диалог), не только Debug.WriteLine.
- Приёмка: цепочка «условие → подтверждение → запись → переход» работает;
  отказ в подтверждении прерывает цепочку.

**Что НЕ трогать в B0:** механизм эпох в `Tick`, пан/зум, `ExpressionVM`,
каркас `ICustomDrawOperation`. Если кажется, что надо трогать — стоп, вопрос

- Демо-проект (несколько секций, насосы шаблонами, аварийные индикаторы,
  TrendView/AlarmView, попапы) собирается кнопкой и работает из пакета без
  ручной сборки схем в коде.
- Нагрузка: 500+ элементов с текстом, Tick/Render в прежнем бюджете.
- Все тесты решения зелёные + новые тесты на секции/сборку (Dev A) и на
  механику привязок/стопов (Dev B, где тестируемо без UI).
